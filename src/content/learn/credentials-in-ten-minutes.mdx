A verifiable credential is a set of claims about a subject, signed by an issuer, held by a holder and shown to a verifier. That is the whole model. Everything else is detail about formats and transport.

## Three roles

- **Issuer**: signs claims it is in a position to vouch for. An employer signs employment; a government signs age.
- **Holder**: keeps the credential in a wallet and decides when to present it. For agents, the holder may be the agent itself or a wallet the agent is allowed to use.
- **Verifier**: asks for specific claims and checks the issuer's signature.

## Why it is different from an access token

An OAuth access token is a key to an API. The resource server usually trusts it because it trusts the authorization server that minted it, and often calls back to check.

A credential is a statement of fact. The verifier trusts it because it can check the issuer's signature itself, without calling the issuer. The issuer never learns where the credential was used.

## Selective disclosure

With SD-JWT VC, the issuer hashes each claim separately. The holder reveals only the claims a verifier asks for; the rest remain digests that cannot be reversed. Paste one into the [SD-JWT decoder](/tools/sd-jwt-decoder/) to see the structure.

## Getting one, showing one

- **OpenID4VCI** is how a wallet obtains a credential from an issuer.
- **OpenID4VP** is how a verifier asks a wallet for a presentation.

Both build on OAuth, so much of what you already know carries over.
